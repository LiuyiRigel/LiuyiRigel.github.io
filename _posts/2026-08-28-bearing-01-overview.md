这是"轴承跨域泛化研究"系列的第 1 篇。本文梳理整个研究的**出发点、领域背景、技术路线选择与论文定位**，回答三个问题：为什么做跨域泛化？有哪些技术路线可选？我们最终选择了哪条路、依据是什么？

---

## 1. 问题背景：模型在"换一台机器"之后失效

滚动轴承故障诊断模型在**同设备、同工况**的随机划分下通常能达到 99% 以上的精度。但工业部署面临的是完全不同的场景：

- **新设备个体**：训练时从未见过的同一型号另一台轴承；
- **新工况**：训练时未经历的新转速、新负载；
- **新故障形态**：训练标签里没有的损伤类型与退化程度。

这种"分布偏移"（domain shift）会让模型显著退化。更危险的是，某些失败模式不是"精度差一点"，而是**系统性把损伤误判为健康**——例如我们早期的本地预验证中，单转速训练的模型在陌生转速下对真实损伤设备的准确率仅 9%。这意味着在工业现场，模型"静默失效"，比"精度低"危险得多。

本研究的核心问题可以概括为：

> **在"未见设备 + 未见工况"的双重偏移下，什么因素真正决定诊断可靠性？**

---

## 2. 领域调研：声发射（AE）与振动两大信号家族

我们首先完成了对**声发射（AE）故障诊断**方向的系统调研（见报告 01），核心发现：

### 2.1 为什么关注 AE？

| 维度 | 振动 | 声发射（AE） |
|---|---|---|
| 物理机理 | 结构响应（低频，<10 kHz 为主） | 材料微损伤释放的弹性波（高频，100 kHz–1 MHz） |
| 早期缺陷灵敏度 | 低（需损伤发展到一定规模） | 高（可捕捉裂纹萌生、微观塑性变形） |
| 抗工况干扰 | 弱（转速/负载变化直接改变响应） | 相对强（局部源，传播路径短） |
| 工业落地 | 成熟（传感器/标准齐全） | 起步（缺乏标准、数据少） |

AE 的"早期灵敏"特性使它成为故障诊断研究中极具价值的方向，但**公开数据稀缺**（尤其是带故障标签的台架数据），这直接影响了研究路径的可行性评估。

### 2.2 六条技术路线的初筛

调研报告梳理出六条可操作的技术路线：

1. **时频分析 + 深度学习**：SSST/CWT 等时频表示 + CNN/Mamba 分类器；
2. **物理先验注入**：把轴承故障特征频率（BPFO/BPFI/BSF）等物理知识编码进网络；
3. **跨域泛化（Domain Generalization, DG）**：在源域上训练，直接推广到未见目标域；
4. **自监督预训练**：用大量无标签数据学习通用表示，再微调；
5. **解调/包络分析 + 诊断**：包络谱、阶比分析等经典信号处理方法；
6. **多传感器融合**：振动 + AE + 电流联合建模。

## 3. 技术路线收敛：从"声发射方向"到"跨域泛化主线"

调研之后，我们做了两轮收敛：

### 3.1 第一轮：数据现实决定方向调整

**关键事实（2026-01 确认）**：AE 2013 公开数据集每个故障类型只有一个轴承。这意味着：

- "故障类型跨轴承泛化"这个题目**不可做**——样本身份与故障类型完全混杂；
- AE 数据只能重定位为"**同轴承跨转速状态识别** + 范式对比"的**辅线**；
- 主线必须迁移到有足够多设备个体的数据集上：**XJTU-SY（15 轴承）与 Paderborn（32 设备）**。

### 3.2 第二轮：控制变量法的"三因素框架"

在确认主线为"跨轴承/跨工况泛化"后，我们进一步把研究问题拆成三个可独立操纵的因素（见报告 02/06 的实施方案）：

| 因素 | 问题 | 变量 |
|---|---|---|
| **R1 呈现形式** | 输入信号怎么表示最抗跨域？ | raw 波形 / STFT / SSST / 包络 / 阶比 |
| **R2 训练覆盖** | 训练数据多覆盖一个目标工况能否修复盲点？ | 单转速 vs 多转速训练 |
| **R3 模型结构** | 结构对跨域泛化影响多大？ | CNN / TCN / LSTM / Transformer / Mamba 谱系 |

这三因素框架贯穿整个研究：**控制变量法**——每次只动一个因素，量化它对跨设备跨转速可靠性的贡献。

## 4. 近三年方法调研：我们的位置

对 2023–2025 年轴承故障诊断方法的调研（报告 23）显示，主流工作分为两类：

- **方法路线（主流）**：提出新的域泛化/域对抗/架构改进（如 DIS 的教师-学生域干扰抑制、各类 Mamba 变体）。这类工作回答"如何学更鲁棒的特征"，但**默认输入表示与训练数据配给是给定的**。
- **数据/表示路线（本文）**：把输入信号的**呈现形式**、训练数据的**工况覆盖**、模型**结构**当作可操纵变量。我们**不提出新模型**，而是回答方法论文不回答的前置问题：在应用任何 DG 方法之前，什么表示、什么数据配给本身决定跨域可靠性？

## 5. 论文定位与创新点论证（诚实版）

在正式写论文前，我们对创新点做了**诚实评估**（报告 08）——避免"自嗨式"创新声明：

### 5.1 三种定位路线

| 路线 | 描述 | 强度 |
|---|---|---|
| A | 提出新理论（软阶次对齐） | 强但风险高 |
| B | 受控基准 + 可证伪规律（本文最终选择） | 中强、稳健 |
| C | 工程配置指南（表示选型 + 覆盖策略） | 中、落地价值高 |

### 5.2 最终选择：B + C 组合

我们的核心贡献不是"又一个新模型"，而是：

1. **受控基准**：Paderborn 32 设备 × 4 工况上的留一轴承基准，5 种协议 × 5 种表示 × 9 种模型，全部逐折持久化（32 折 × 3 种子）；
2. **三因素解耦证据**：呈现、覆盖、结构各自独立变化时的量化贡献；
3. **可证伪规律**："单转速训练 → 陌生转速系统性误判健康；多转速训练 → 修复"（跨架构一致）；
4. **工程指南**：面向未见设备 + 未见转速部署的最优配置，以及与 DG 方法的互补关系。

### 5.3 可行性评估

基于实验资产盘点（报告 24），我们评估了三个候选期刊（Sensors / Machines / MST）的适配度，结论是：以"受控基准 + 数据/表示层发现"为主线的方案，比"新方法 + 有限数据集"更有说服力，也更难被审稿人用"数据集单一"一击致命。

## 6. 整体研究路线图

```
文献调研（AE 领域 + 近三年方法）
    ↓
理论构建（跨工况泛化的物理与数学 → 软阶次对齐）
    ↓
模型设计（SSST 前端 + 轻量 Mamba → WaveBag 架构）
    ↓
实验验证（多数据集 × 多协议）
    ├── XJTU-SY（振动，跨轴承/跨工况）← 辅线
    ├── AE 台架（跨转速状态识别）    ← 辅线
    ├── 变速振动（Huang-Baddour）    ← 辅线
    ├── 多域数据集（Lee 2024）       ← 辅线
    └── Paderborn（32 设备）         ← 主线（统一 Benchmark）
    ↓
论文写作（初稿 v0 → v1 → 投稿）
```

后续系列文章将按这条路线逐块展开：第 2 篇讲物理与数学基础，第 3 篇讲模型设计，第 4 篇讲数据集，第 5 篇讲辅线实验，第 6–7 篇讲 Paderborn 主线与 Batch1 结果，第 8 篇讲论文写作与 DIS 复现对照。

---

## 7. 一句话总结

> 轴承故障诊断的跨域泛化问题，答案可能不在"更聪明的模型"，而在**输入表示、训练数据覆盖与模型结构的正确组合**——这是本系列后续所有文章要展开论证的核心命题。
